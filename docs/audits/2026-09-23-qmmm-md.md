QM/MM molecular-dynamics performance audit — 23 September 2026
=============================================================

Audited checkout: `b4495f8`. Priority: QM/MM molecular dynamics, as requested.
No implementation changes were made. Timings below are exploratory measurements,
not production speedup guarantees. The user's production QM region, electronic
method, hardware and trajectory were not supplied.

The best near-term approach is to preserve the current electrostatic model while
reducing wrapper overhead and benchmarking ORCA settings. The strongest larger
development opportunity is multiple-time-step integration of a high-minus-low QM
correction, with the inexpensive reference evaluated every inner step. Simply
skipping QM evaluations or shortening the charge cutoff is not an equivalent
accuracy optimization.

**What the implementation already does well**

The MD path uses OpenMM `PythonForce` to evaluate physical energy and forces at
the requested geometry, including barostat trial geometries. It caches results
for exactly identical coordinates and periodic cells
([provider](/home/louie/skunkworks/openmmqmmm/openmmqmmm/openmm/rpmd_force.py:65)).
ORCA normally reuses the preceding GBW orbitals
([orbital preparation](/home/louie/skunkworks/openmmqmmm/openmmqmmm/orca.py:771)).
Link-atom and virtual-charge force projections have finite-difference tests.
Preserve these features when optimizing.

**Confirmed resource-configuration issue**

[`OpenMMTheory.set_numcores()`](/home/louie/skunkworks/openmmqmmm/openmmqmmm/openmm/theory.py:892)
only changes `self.numcores`; Context construction actually uses the CPU
`properties["Threads"]` value assigned at initialization. Consequently
`qmmm.set_numcores(...)` does not update the MM thread setting as its docstring
promises. Fix the property as well and handle an existing Context explicitly.
Until then, choose MM threads on `OpenMMTheory` construction.

Likewise, `openmm_md(platform="CUDA", theory=qmmm)`
[reuses the existing MM theory](/home/louie/skunkworks/openmmqmmm/openmmqmmm/openmm/md.py:782)
and does not switch its platform. Set `platform` and precision on
`OpenMMTheory` itself. These configuration traps can explain absent speedups
when users believe they have enabled more MM threads or GPU execution.

**1. Profile and tune the existing electronic calculation**

[ORCATheory.run](/home/louie/skunkworks/openmmqmmm/openmmqmmm/orca.py:673)
extracts SCF iterations and
[ORCA timings](/home/louie/skunkworks/openmmqmmm/openmmqmmm/orca.py:703), but does
not retain them as a useful per-step profile. Record total callback wall time,
imaging, input writing, ORCA launch/runtime, SCF, QM and point-charge gradients,
parsing, native MM time, reporter time, and cache hit/miss counts. Benchmark warm
displaced snapshots; identical-geometry repetitions understate production SCF
work.

Sweep 1/2/4/8 ORCA processes on representative snapshots rather than assuming
more cores help. Allocate OpenMM CPU threads and MPI ranks within the available
resources. Use a local scratch directory per trajectory/worker and retain its
GBW between steps; retain restart data outside disposable scratch. The ORCA
manual recommends local scratch and describes MPI resource handling
([parallel execution](https://orca-manual.mpi-muelheim.mpg.de/contents/essentialelements/parallel.html)).
Selecting OpenMM CUDA accelerates the MM component; this wrapper still launches
ORCA as a separate executable. Measure the fraction of step time spent in MM
before expecting a large total benefit.

Keep TightSCF initially. Warm starting is already enabled, and reducing SCF
accuracy can affect forces before energy differences look concerning. In the
small benchmark below, cold versus warm identical-geometry energies agreed
within 8e-10 Eh, yet force components differed by up to 6e-6 Eh/bohr. For
open-shell systems, also verify the same intended SCF/spin solution.

**2. Eliminate unconditional MD readbacks**

The [classical MD loop](/home/louie/skunkworks/openmmqmmm/openmmqmmm/openmm/md.py:1317)
calls `simulation.step(1)` and
[`_current_step_coords`](/home/louie/skunkworks/openmmqmmm/openmmqmmm/openmm/md.py:1184)
every step. That helper requests both positions and energy regardless of output
cadence. Step to the next trajectory, special-atom, energy or restart event;
request only the state fields required there. Reuse a state when several
reporters need it.

This should remove Python/host synchronization and redundant native MM work.
It does **not** halve classical QM calculations: a runtime probe with Verlet,
LangevinMiddle and NoseHoover found that the extra endpoint evaluation is reused
by the next integration step through the existing cache. Preserve cache keys
including the instantaneous box and preserve full-potential barostat trials.

**3. Preserve the field while reducing wrapper work**

[Periodic imaging](/home/louie/skunkworks/openmmqmmm/openmmqmmm/periodic_embedding.py:69)
runs on every evaluation and loops over bonds/molecules, computes a NumPy mean
per component, then applies translations per molecule. Precompute graph/index
arrays and vectorize component centers and translations. An orthorhombic fast
path could help if it preserves minimum-image choices; keep the triclinic path
and winding-network checks. Synthetic water-box timings, fastest of three:
41 ms at 3,001 atoms, 212 ms at 30,001, and 325 ms at 99,991. These measure the
existing routine, not a demonstrated optimized implementation.

ORCA output is scanned separately for errors, warnings, termination, energies,
optional properties and timings. Consolidate parsing while retaining failure
checks. The interface also
[copies the last output every call](/home/louie/skunkworks/openmmqmmm/openmmqmmm/orca.py:432);
make retention cadence configurable. Exact-zero point charges could be filtered
before backend submission, with gradients scattered back to original indices;
benefit depends on their fraction and ORCA's own filtering. Do not omit nonzero
MM charge gradients or cap/virtual-site projections.

**4. Electronic and embedding approximations tested**

ORCA 6.1 normally enables RI-J for pure DFT and RIJCOSX for hybrid DFT when the
functional is selected in simple input. Thus the README's `r2SCAN-3c` workflow
does not automatically gain another RI speedup. Some integration tests explicitly
use `NORI`. Removing that restriction is a candidate when matching a NORI
reference is unnecessary
([ORCA RI documentation](https://www.faccts.de/docs/orca/6.1/manual/contents/essentialelements/RI.html)).

Serial ORCA 6.1.1, PBE/def2-SVP TightSCF, six methanol QM atoms plus three water
point charges, one observation per stage:

| Stage | NORI | RI-J | SCF iterations, both |
|---|---:|---:|---:|
| Cold geometry | 2.218 s | 1.998 s | 11 |
| Warm identical geometry | 1.333 s | 1.211 s | 3 |
| Warm displaced geometry | 2.265 s | 1.626 s | 8 |

RI-J shifted the absolute energy by about -0.094 kcal/mol, but changed the energy
difference between the two geometries by only -0.000677 kcal/mol. Full QM/charge
gradient relative L2 differences were 0.220–0.233%, with maximum component
difference 4.72e-5 Eh/bohr. These two geometries do not establish reaction-path
or trajectory accuracy.

The ORCA manual recommends considering FMM for environments above about 10,000
charges, with default expansion order MAM=20
([FMM documentation](https://www.faccts.de/docs/orca/6.1/manual/contents/multiscalesimulations/fmm.html)).
I verified `FMM-QMMM` through this repository's external point-charge interface,
including readable QM and point-charge gradients. The test used the solvated
lysozyme fixture: 26,131 real atoms, six QM atoms, one cap, 26,131 charge sites
after boundary corrections, BP86/def2-SVP TightSCF, serial ORCA and two OpenMM
CPU threads.

| Warm identical-geometry measurement | Baseline | FMM |
|---|---:|---:|
| Full standalone QM/MM wall time | 10.120 s | 11.455 s |
| ORCA reported total | 5.600 s | 5.199 s |
| ORCA point-charge gradient | 2.7 s | 2.4 s |

FMM-minus-baseline energy was 8.45e-7 Eh = 0.000530 kcal/mol. Force-component RMS
difference was 3.17e-8 Eh/bohr, maximum 2.52e-6; maximum on real QM atoms was
1.61e-7. This is encouraging single-geometry accuracy evidence, **not a measured
end-to-end speedup**. Timings overlapped other tests and include standalone MM
context creation. Benchmark several moving geometries and larger QM regions
before adopting it. FMM still represents the existing finite embedding field;
it does not add periodic QM electrostatics.

**5. Larger development option: multiple-time-step QM/MM**

Split the physical potential as
`U = U_MM_modified + U_QM_low + (U_QM_high - U_QM_low)`.
Evaluate native MM and the cheap embedded QM reference each inner step; evaluate
the expensive difference less often. Both QM levels must use consistent charge
fields, caps, and force projections. Candidate references include a cheaper DFT
method/basis or a validated semiempirical model with the required embedding and
charge-gradient support. Their usefulness must be measured for the intended
chemistry.

The difference must vary slowly enough for MTS. Trial outer/inner ratios of two,
then four, are experiments rather than guaranteed safe defaults. For a ratio m,
the ideal cost becomes roughly `T_low + T_high/m` per inner step, plus MM and
overhead; the achievable speedup is smaller than m. OpenMM supplies force-group
[MTS integrators](https://docs.openmm.org/latest/api-python/generated/openmm.mtsintegrator.MTSIntegrator.html),
and the approach has precedent in
[ab initio MTS research](https://arxiv.org/abs/1312.1284).

Do not simply assign the entire present QM force to a slow group. The
[coupling setup removes internal QM bonded MM terms](/home/louie/skunkworks/openmmqmmm/openmmqmmm/qmmm.py:711),
so the QM calculation supplies stiff internal bond forces as well as slower
environmental response. Keep a fast reference for those motions. Preserve the
full physical potential for energy reports and barostat acceptance.

**Accuracy limitations and tests that matter before adopting shortcuts**

`truncated_pc` caches separate constant energy and gradient corrections
([cached application](/home/louie/skunkworks/openmmqmmm/openmmqmmm/qmmm.py:1231)).
Between refreshes, the returned gradient is generally not the derivative of the
reported energy. Existing boundary tests validate refreshes and identical
geometry reuse. A synthetic existing test fixture with radius 0.1 Å and refresh
interval 50 gives a maximum analytical-versus-finite-difference discrepancy of
1.676 Eh/bohr on cached energy calls. The magnitude is artificial, but the
inconsistency is structural. Classical MD and RPMD already reject this option.
Retain that rejection. A conservative far-field approximation needs a defined
coordinate-dependent energy and all its force derivatives.

Periodic embedding is a finite, molecule-imaged charge cluster; only MM uses its
configured PME/Ewald treatment. Image switches can be discontinuous. This is
[already documented](/home/louie/skunkworks/openmmqmmm/docs/source/guide/qmmm.md:77).
Smaller cells, smaller charge radii, mechanical embedding, deleting dipole
corrections, reducing the QM region, or increasing timestep are changes to the
model or dynamics requiring independent convergence evidence.

The real-ORCA energy assertion
[uses np.isclose with default rtol](/home/louie/skunkworks/openmmqmmm/tests/test_QM_MM_openmm.py:52).
At about -115.8 Eh its effective tolerance is about 0.73 kcal/mol despite
`atol=2e-6`; set `rtol=0` when an absolute numerical regression tolerance is
intended. Passing the present suite alone cannot certify tighter accuracy.

**If the MD workflow includes RPMD**

Contraction already exists via `rpmd_qm_num_copies`, but contracts the entire QM
force. For reliable aggressive contraction, add a cheap QM reference on every
bead and contract only the high-minus-low difference, then converge bead counts
([ab initio contraction research](https://arxiv.org/abs/1512.00473)).

[The RPMD energy reporter](/home/louie/skunkworks/openmmqmmm/openmmqmmm/openmm/md.py:122)
calls `getTotalEnergy()`, which evaluates full-bead potentials. An eight-bead
centroid-contracted probe required eight additional full-bead QM evaluations at
an energy report. Separate full-ring energy cadence from trajectory output and
share results between reporters. This preserves propagation while avoiding a
reporting cost that can erase contraction savings.

The documentation's `2N` QM-jobs-per-step estimate is an upper description of
potential evaluations, not necessarily fresh ORCA jobs. A four-bead probe used
eight fresh evaluations on the first step, then four per step because cached
endpoints were reused. Measure actual cache misses when estimating cost. adQTB
is a distinct NQE approximation, not an accuracy-equivalent RPMD speed switch.

**Secondary finding outside the MD hot path**

[OpenMMTheory.run](/home/louie/skunkworks/openmmqmmm/openmmqmmm/openmm/theory.py:1567)
recreates its Simulation/Context every standalone evaluation. Context reuse
with explicit invalidation is worth investigating for optimization/snapshot
batches, but classical MD already has a persistent Context. A noisy two-thread
CPU trial over 12 solvated-protein geometries took 48.2 s fresh versus 57.9 s
reused, so this audit did not establish a speedup. Do not use that architectural
observation as a measured MD gain.

Before production changes, collect representative equilibrium and reactive
snapshots from the actual system. Measure relative energies, reactive-region
and environmental force RMS/max errors, SCF state, median/p95 time per step,
and short NVE drift at fixed timestep. For MTS also converge the outer timestep;
for NVT compare distributions and intended observables with uncertainty
estimates rather than coordinate-by-coordinate trajectory agreement. Starting
screening targets such as relative-energy errors below 0.1 kcal/mol and force
RMS changes below 1% are proposed gates, not universal guarantees; tighten them
to the scientific observable and inspect localized errors separately.

Recommended implementation order: expose profiling; remove per-step readbacks
and vectorize imaging; benchmark resource allocation, RI/FMM where relevant;
then prototype conservative delta-QM MTS if substantial acceleration is still
needed. Raw ORCA benchmark measurements are preserved in the adjacent JSON file.
